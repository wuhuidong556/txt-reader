# TXT 朗读器

> 把 `.txt` 丢进来，就有人念给你听。中文优先，边合成边播放，长文不卡。

一个 Windows 桌面听书工具：导入 TXT → 自动识别编码 → 切章分节 → 用接近真人的中文神经音色朗读，
断网自动切到系统离线音色，还能把整本导出成一个 mp3。

```
导入 TXT  →  自动识别编码（UTF-8 / GBK / UTF-16）  →  切分段落
          →  边合成边播放（后台预取后 3 段）        →  记进度、可续读
          →  可选：导出整本 mp3
```

## 特性

- **两条嗓子，自动接管**
  在线走微软 Edge 神经音色（晓晓 / 云希 / 云健 / 云扬 / 东北话晓北 / 陕西话晓妮 等 8 种），
  断网或请求失败时**自动切到 Windows 自带离线音色**，不会中途哑掉。
- **编码不用你操心**
  中文 TXT 常年三分天下（UTF-8 / GBK / UTF-16），读错就是一屏问号。
  这里自动探测，并保留手动指定编码重读的余地。
- **边合成边播，不等人**
  整本书先合成完再播是行不通的（几小时音频、内存爆炸）。这里按句切段，
  播第 N 段时后台已经在合成 N+1、N+2、N+3。实测：**合成一段 28 秒的音频约 1.9 秒**，预取永远跑在播放前面。
- **目录、跳读、续读**
  自动识别「第一章 / 1.1 / 序言 / 后记 / Chapter 1」等标题生成目录；
  **点正文任意一段就跳过去读**；关掉程序下次打开接着上次那一段。
- **导出整本 mp3**
  后台串行合成 + 拼接，进一个文件，走路也能听。
- **磁盘缓存**
  每段音频按（文本+音色+语速）缓存，重听、导出直接复用，不重复请求。
- **译成英文 · 按高考难度改写**
  接 DeepSeek 逐段改写，四档难度（90 分以下 / 90–105 / 105–120 / 120–135），
  每档限定用词与句法；译文按段落哈希缓存，重跑不重复花钱。
  产物各勾各的：中英对照（txt + docx）、纯英文（txt + docx）、英文音频、中文音频
  —— 只出中文音频时**完全不调 API**。
- **中英对照书：中文 / English 一键切换**
  译出来的对照稿会被自动识别成「对照书」，底部多一个 `中文 | English` 开关：
  中文模式只念中文、英文模式只念英文（英文音色），切换时当前段立刻换语言重念。
- **docx 仓库**
  译文 docx 自动复制一份到项目根的 `docx\`，左侧栏直接可见，点开就是 Word。

## 快速开始

需要 **Python 3.10+**（开发环境为 3.13）。

```bash
git clone https://github.com/wuhuidong556/txt-reader.git
cd txt-reader
pip install -r requirements.txt

python app.py                # 开窗口运行
python app.py --shortcut     # 在桌面创建一个快捷方式
python app.py --no-window    # 只起服务（调试用）
```

启动后点右上角 **导入 TXT** 选一个文件即可。

> **想用「译成英文」**：在 `data/apikey.txt` 里写一行 DeepSeek 的 API key（`sk-...`），
> 再点右上角「译成英文」。不填 key 也照样能听书，只是不能翻译。

> **没有 ffmpeg 也能用。** 在线音色产出 mp3、离线音色产出 wav，浏览器两种都能直接播；
> 导出整本时若无 ffmpeg 会自动退化为 MP3 字节拼接（edge-tts 输出是同码率 CBR，帧边界可以直接相接）。
> 装了 ffmpeg 则用它做更规范的拼接。

## 目录结构

```
txt-reader/
├─ app.py            主程序：窗口 + 托盘 + 单实例 + 桌面快捷方式
├─ server.py         本地 HTTP：界面 / API / 音频流（含 Range，可拖动）
├─ engine.py         语音引擎：切分、Edge TTS、SAPI 兜底、预取流水线
├─ library.py        书库：导入、编码识别、章节切分、进度落盘
├─ panel/            前端（原生 HTML/CSS/JS，无框架、无构建）
│  ├─ index.html
│  ├─ app.js
│  └─ style.css
├─ books/            导入的正文副本（.gitignore）
├─ cache/            音频缓存（.gitignore）
├─ data/library.json 书库与阅读进度（.gitignore）
└─ exports/          导出的整本 mp3（.gitignore）
```

## 几个设计选择（为什么这么做）

**为什么不在 Python 里播音频，而用浏览器 `<audio>`？**
音频要支持边合成边播、要能拖动进度（HTTP Range），现代的 `<audio>` 一句就能干完，
而且**不引入任何额外音频依赖**。这对「依赖越少越好、能开源」是决定性的。

**为什么把 ffmpeg 做成可选的？**
Python 生态里的 `imageio-ffmpeg` 附带的是 **gyan.dev essentials 构建，属 GPL v3**（含 x264/x265）。
把它打进发行包会让整个包受 GPL 约束。而本应用其实不需要它 —— 于是干脆做成可选，
**发行版不带任何 GPL 二进制**，许可证干净。

**为什么用本地 HTTP 而不是 `file://` 或 IPC？**
音频流、静态资源、API 三件事一套 HTTP 全解决；只绑 `127.0.0.1` + 随机 token，
别的网页打不开也读不到你本地的书。

## 常见问题

**Q：一打开就是一屏问号？**
编码识别偶尔会踩坑（尤其是半路被截断的 GBK 文件）。文件已复制进 `books/`，可以手动指定编码重读
（`library.import_txt(path, encoding="gb18030")`），或先用编辑器另存为 UTF-8。

**Q：点播放没声音 / 卡住？**
第一次点某一段时，后端要先把这段合成出来（通常 1–2 秒）。若长时间没反应，看状态栏提示；
在线音色失败会自动转离线，两条都失败才会报错。

**Q：缓存吃了多少盘？**
界面右上角有显示。缓存全在 `cache/`，直接删掉即可（下次听会重新合成）。

**Q：能读 PDF / EPUB 吗？**
目前只有 TXT。PDF/EPUB 需要另加解析层，见路线图。

**Q：为什么不做成网页版？**
因为要读本机文件、要持续后台合成、要托盘常驻 —— 桌面形态更合适。
